# Phase 1 Plan 01: Voice Session Reliability

## Objective

Make the already-integrated Android voice flow deterministic: a user gets no more than three turns, sees accurate state and recovery guidance, must rate the session before it closes, and receives the generated report.

## Tasks

### Task 1: Audit client state transitions

**Files:** `mobile/src/app/session.tsx`, `mobile/src/lib/api.ts`

1. Confirm there is no UI state that can leave the primary control disabled without a failure message or recovery action.
2. Ensure all turn, feedback, recap, and audio-state copy reflects the three-turn rule.
3. Keep text replies usable when TTS fails, and do not expose provider or server internals.

### Task 2: Enforce server authority for the three-turn flow

**Files:** `backend/app/api/sessions.py`, `backend/app/services/session_service.py`

1. Verify server-side turn caps and end-state validation match the mobile UI.
2. Verify feedback cannot complete an empty or unauthorized session.
3. Ensure recap generation failure results in an honest saved/unsaved outcome without a stuck session.

### Task 3: Validate build gates

**Files:** `mobile/package.json`, `backend/requirements.txt`

1. Run mobile lint and TypeScript checks.
2. Run backend syntax/import checks without reading secret files.
3. Record results in the plan summary.

## Acceptance Criteria

- Three turns are enforced by both UI and backend.
- Feedback is required for session closure and report generation.
- Expected provider/network/audio failures are recoverable from the user’s point of view.
- Mobile lint/type checks and backend import checks pass.
